# 需求文档

> 玉米（CORN）—— 简易通用资源管理系统

## 1. 项目背景

玉米（CORN，Common Resource Negotiator）是一款面向个人与团队的**通用资源预算与消耗管理系统**。
通过「预算 → 配额 → 消耗记录」的主轴，帮助用户在任意活动（学习、工作、项目、生活目标）中对时间、人力、资金等成本进行**计划、分配与追踪**。

## 2. 项目目标

### 2.1 业务目标

- 提供统一的「资源-活动-消耗」领域内核，覆盖计划与执行两个阶段。
- 支持个人单机使用、团队 SaaS 使用、企业私有化部署三种形态。

### 2.2 工程目标（架构目标）

- **统一逻辑内核**：业务逻辑集中在一个可复用 crate 中，三种部署形态共享同一份代码。
- **多端入口**：未来可快速产出 Web、移动、桌面、本地独立运行四类入口。
- **多部署形态**：同时支持 SaaS 多租户、私有化部署、本地独立运行。
- **契约驱动**：以 OpenAPI 3.1 规范作为前后端契约，前端通过自动生成的 SDK 复用。

## 3. 目标用户与角色

| 角色 | 场景 | 关注点 |
|------|------|--------|
| 个人用户 | 本地独立运行 | 数据本地化、无需注册、零运维 |
| 团队负责人 | SaaS 多租户 | 多成员协作、租户隔离、按量计费 |
| 企业 | 私有化部署 | 数据自主、合规、内网部署 |

## 4. 核心概念

| 概念 | 含义 |
|------|------|
| **资源** | 活动中成本的统称（时间、人力、资金等所有需要控制用量的成本） |
| **类别** | 资源的种类划分（如「人力」单位为「人天」，「资金」单位为「元」） |
| **空间** | 互斥独立的活动容器（如「学习」「工作」），各自独立预算 |
| **活动** | 为达成目的的行为集合，支持父子层级；子活动配额之和 ≤ 父活动配额 |
| **预算** | 在空间内为某类别资源创建的总量计划 |
| **配额** | 将预算划分给具体活动的份额 |
| **消耗记录** | 手动记录的资源消耗，记录之和等于活动消耗总额 |
| **记录器** | 自动按规则记录消耗（如每天一条时间消耗记录） |
| **标签** | key-value 形式的辅助分类，用于检索与匹配 |

## 5. 功能需求

### 5.1 资源管理

- **FR-R1** 管理类别（Category）：创建/查询/修改/删除，含 code、name、unit。
- **FR-R2** 在空间内创建预算（Budget），指定类别、空间、金额、标签。
- **FR-R3** 通过标签对预算进行过滤检索。
- **FR-R4** 系统初始化时预置默认类别（人力/资金）。

### 5.2 空间管理

- **FR-S1** 管理空间（Space）：创建/查询/修改/删除，含 code、name。
- **FR-S2** 系统初始化时预置默认空间（default/默认）。
- **FR-S3** 空间之间预算互斥独立，不可跨空间调配。

### 5.3 活动管理

- **FR-A1** 管理活动（Action）：创建/查询/修改/删除，含名称、空间、父级、标签。
- **FR-A2** 支持活动的父子层级关系。
- **FR-A3** 子活动配额之和不得超过父活动配额。
- **FR-A4** 通过标签对活动进行过滤检索。

### 5.4 配额管理

- **FR-Q1** 将预算金额以配额（Quota）形式划分给活动。
- **FR-Q2** 查询活动下所有配额及其已消耗/剩余金额。
- **FR-Q3** 配额剩余金额 = 配额金额 − Σ 关联消耗记录金额。

### 5.5 消耗记录

- **FR-C1** 手动创建消耗记录（Record），关联配额、记录金额。
- **FR-C2** 查询活动下所有消耗记录（含时间、金额）。
- **FR-C3** 消耗记录不可超额（超出配额余额时拒绝创建）。

### 5.6 自动记录器

- **FR-RC1** 创建记录器（Recorder），绑定类别、空间、活动、标签匹配条件、配置。
- **FR-RC2** 记录器按规则自动创建消耗记录。

### 5.7 多租户（仅 SaaS 形态）

- **FR-T1** 租户隔离：所有数据按 tenant_id 隔离，跨租户不可见。
- **FR-T2** 租户上下文中间件：从请求中解析 tenant_id 注入上下文。
- **FR-T3** 租户初始化：每个租户独立预置默认空间与类别。

## 6. 非功能需求

### 6.1 部署形态

| 形态 | 入口 | 业务逻辑 | 数据库 |
|------|------|---------|--------|
| SaaS | corn-server 二进制 | corn-core crate | PostgreSQL + 行级多租户 |
| 私有化 | corn-server 二进制（Docker） | corn-core crate | PostgreSQL（单租户或带租户） |
| 本地独立 | Tauri 安装包 | corn-core crate 直接嵌入 Tauri 进程 | SQLite 文件 |

### 6.2 性能

- 单实例支持 ≥ 1000 QPS（典型资源 CRUD）。
- 数据库连接池化，可配置。

### 6.3 可维护性

- OpenAPI 3.1 契约自动生成，前端 SDK 自动产出。
- 数据库迁移脚本版本化管理（sqlx-migrate）。

### 6.4 安全

- 所有 API 默认要求鉴权（SaaS/私有化形态）。
- 多租户严格隔离，单测覆盖跨租户越权场景。

## 7. 约束与假设

- 假设 1：消耗记录创建即不可修改，仅可新增冲销记录（暂以「不可修改」实现）。
- 假设 2：层级配额校验仅做「子配额之和 ≤ 父配额」静态校验，不处理并发分配竞态。
- 约束 1：现有 Java/Spring Boot 实现将被整体替换，仅作为领域契约参考。
- 约束 2：MVP 阶段鉴权采用简单 Bearer Token，后续可扩展 OAuth2/OIDC。
